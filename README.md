# Basecamp — Startup Project Manager

A simple, no-training-needed project board for a startup team: sign in, create teams, add activities, assign work, and track progress. Overdue work is detected automatically. Each team is a fully separate workspace with its own members, activities, and dashboard.

## Features

- **Auth** — email/password signup & login, "Continue with Google," mobile number + OTP login, forgot/reset password, logout.
- **Profile** — full name, username, email, mobile, bio, role/designation, avatar, notification preferences, change password — all editable from a profile menu in the top-right corner.
- **Multiple independent teams** — create as many teams as you like. Each team has its own members, activities, dashboard, and settings. Nothing from one team ever appears in another. Switch teams instantly with the team switcher in the sidebar.
- **Roles** — Owner (full control), Admin (manage members/activities/settings), Member (view team work, manage their own activities).
- **Add members** by email or username. If they don't have an account yet, an invite is created and they join automatically the moment they sign up with that email.
- **Activities** — quick add with title, description, assignee, start date, and deadline. Status changes with one dropdown, no page reload.
- **Automatic Due Work** — any activity past its deadline that isn't Complete is automatically shown as "Due Work" everywhere (dashboard, board, member view) — nothing to mark manually.
- **Dashboard** — per team: total/To Do/In Progress/Complete/Due Work counts, overall completion %, per-member progress bars, upcoming deadlines, recent activity.

## Run locally

Requires [Node.js](https://nodejs.org) 18+ and a Postgres database (local, [Neon](https://neon.tech), Render Postgres, etc.).

```bash
npm install
cp .env.example .env
# edit .env: set DATABASE_URL to your Postgres connection string
#            set JWT_SECRET to any long random string
npm start
```

Then open **http://localhost:3000**, click **Create an account**, and you're in. The database schema is created automatically on first boot — no migration step needed.

### Using your Neon database

Paste your Neon connection string into `.env` as `DATABASE_URL`:

```
DATABASE_URL=postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require
```

`.env` is git-ignored, so this never gets committed.

> **Security note:** if a database connection string is ever pasted somewhere outside of `.env` (a chat, a doc, a ticket), treat the password as compromised and rotate it from your Neon project's **Settings → Reset password** — the same way you'd rotate any other leaked credential.

## Project structure

```
server.js            Express app bootstrap — mounts routes, serves the frontend
db/
  schema.sql          Full Postgres schema (users, teams, members, invites, tasks)
  pool.js              Connection pool + automatic schema bootstrap on boot
middleware/
  auth.js              JWT cookie auth, team-membership & role checks
routes/
  auth.js              Signup, login, logout, forgot/reset password, mobile OTP, Google OAuth
  users.js             Profile, change password, notification settings, "my teams"
  teams.js             Create/update/delete teams, members, roles, invites
  tasks.js             Activity CRUD, scoped per team
  dashboard.js          Aggregated per-team dashboard stats
lib/
  taskStatus.js         Shared "Due Work" / overdue computation
public/
  index.html            Auth screens + main app shell (single page app)
  style.css              Design system
  app.js                 All frontend logic
render.yaml            Render.com blueprint
```

## Deploy to Render

### 1. Push to GitHub

```bash
git remote add origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

### 2. Create the Render service

Go to <https://dashboard.render.com/blueprints> → **New Blueprint Instance** → connect this repo. Render reads `render.yaml` and creates a Web Service (build: `npm install`, start: `npm start`).

### 3. Set environment variables

In the Render dashboard, under the new service → **Environment**, set:

| Key | Value |
|---|---|
| `DATABASE_URL` | Your Neon (or other Postgres) connection string |
| `JWT_SECRET` | Auto-generated by the blueprint, or set your own long random string |
| `NODE_ENV` | `production` |
| `BREVO_API_KEY` or `RESEND_API_KEY` | Recommended for deployed email delivery on Render free |
| `SENDER_EMAIL` | Sender address verified with your email API provider |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | Optional for local development or paid hosts that allow outbound SMTP |

`JWT_SECRET` signs login session cookies — keep it private and don't reuse it elsewhere.

### 4. (Optional) Enable "Continue with Google"

1. Create OAuth credentials at <https://console.cloud.google.com/apis/credentials> → **Create Credentials → OAuth client ID → Web application**.
2. Add an **Authorized redirect URI**: `https://<your-render-url>/api/auth/google/callback`.
3. Set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_CALLBACK_URL` (the same redirect URI) in Render's environment variables.

Without these three variables set, the Google button shows a friendly "not configured yet" message instead of failing silently.

### On email delivery and mobile OTP

Signup email verification and password reset both send real emails when Brevo, Resend, or SMTP is configured. On Render's free plan, use Brevo or Resend because free web services block outbound SMTP ports (`25`, `465`, and `587`). Gmail SMTP can still work on localhost, but it will not send from a free Render deployment.

- **Mobile OTP login** creates a 6-digit code and returns it directly in the API response (and logs it server-side) instead of texting it.

For local development only, signup email verification can fall back to showing the code in the UI when no email provider is configured. For real production use, configure an HTTPS email provider and an SMS provider:

- Email: [Brevo](https://www.brevo.com) or [Resend](https://resend.com) — used by signup verification, password reset, invites, and task notification emails.
- SMS: [Twilio](https://www.twilio.com) or similar — send from `routes/auth.js`'s `otp/send` handler.

## API reference

All routes are prefixed `/api`. Auth uses an httpOnly session cookie set on login/signup — no bearer tokens to manage on the frontend.

| Method | Path | Purpose |
|---|---|---|
| POST | `/auth/signup` | Create account (email + password) |
| POST | `/auth/login` | Log in (email/username + password) |
| POST | `/auth/logout` | Clear session |
| GET | `/auth/me` | Current user |
| POST | `/auth/forgot-password` | Create a password reset link |
| POST | `/auth/reset-password` | Reset password with a token |
| POST | `/auth/otp/send` | Create a mobile login code |
| POST | `/auth/otp/verify` | Verify code and log in / create account |
| GET | `/auth/google` | Start Google OAuth |
| GET | `/auth/google/callback` | Google OAuth callback |
| GET / PUT | `/users/me` | View / edit profile |
| PUT | `/users/me/password` | Change password |
| PUT | `/users/me/notifications` | Update notification preferences |
| GET | `/users/me/teams` | Teams the current user belongs to |
| GET | `/users/search?q=` | Search users by email/username |
| POST | `/teams` | Create a team |
| GET / PUT / DELETE | `/teams/:teamId` | View / edit / delete a team |
| GET / POST | `/teams/:teamId/members` | List / add members |
| PUT / DELETE | `/teams/:teamId/members/:userId` | Change role / remove member |
| DELETE | `/teams/:teamId/invites/:inviteId` | Cancel a pending invite |
| GET / POST | `/teams/:teamId/tasks` | List / create activities |
| PUT / DELETE | `/teams/:teamId/tasks/:taskId` | Update / delete an activity |
| GET | `/teams/:teamId/dashboard` | Aggregated dashboard stats for the team |

"Due Work" status is never stored — it's computed live from `deadline` vs. today's date whenever activities are read, so it can never drift out of sync.
